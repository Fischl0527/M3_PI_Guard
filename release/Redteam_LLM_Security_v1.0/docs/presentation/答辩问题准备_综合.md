# 答辩问题准备_综合

## 1. 为什么不只靠提示词加固？
提示词加固主要约束模型文本输出，但工具调用场景的风险发生在执行边界。只要 ToolCall 已经指向 secrets、外发接口或 run_code，就需要独立的行为监督层进行裁决。

## 2. Guard 和传统关键词过滤有什么区别？
关键词过滤只看文本片段。M3-PI Guard 同时看工具类型、路径、endpoint、参数、上下文载体、工具输出和敏感数据流，并输出可解释 reasons。

## 3. 为什么使用 allow / ask / deny 三档？
allow 保持正常任务可用，deny 阻断明确高危行为，ask 用于外发类或写入类中等风险动作，便于后续接入人工确认或更细粒度授权。

## 4. 为什么 run_code 默认 deny？
代码执行具有最高副作用风险，可能读写本地环境、发起网络访问或规避工具沙箱。当前原型以安全优先，因此强制拒绝。

## 5. 如何处理正常的 public 文件读取？
read_file 访问 sandbox/public 默认 allow，访问 sandbox/secrets 强制 deny。这样既保留摘要、翻译、抽取等正常任务，又阻断秘密路径读取。

## 6. 为什么 call_api 只允许 mock endpoint？
评测靶场强调可复现和无真实外部副作用。非 mock endpoint 可能造成真实外发，因此在当前策略中强制 deny。

## 7. 如何识别 JSON/RPC 结构化注入？
检测 instruction、system、developer、tool、function_call、method、params、execute、next_step 等字段。如果这些字段出现在不可信载体中，会提高 structured_injection_detected 风险。

## 8. 如何识别多语言或字符混淆？
normalizer 做 Unicode NFKC、零宽字符删除、大小写和空格归一；detector 进一步识别中英混合、日韩俄片段加工具词、以及拼音表达的“忽略、发送、读取”等规避模式。

## 9. 如何判断敏感数据流？
dataflow 会从 observation、document_content 和 tool_call 参数中提取 M3_CANARY、secret、api_key、token、password 等标签；如果标签进入 send_email 或 call_api，则触发 deny。

## 10. 为什么 Qwen2.5 代表样本 baseline ASR 不高？
代表样本规模较小，且部分攻击需要特定模型行为才能触发。stub 全量矩阵用于覆盖攻击面，Qwen2.5 样本用于展示真实模型倾向，两者定位不同。

## 11. WRS 的意义是什么？
WRS 是综合韧性得分，用于把攻击成功、未授权工具调用、数据泄漏、误报和阻断效果合并成一个便于比较的指标。它不是替代细分指标，而是总览指标。

## 12. 当前系统的主要局限？
规则型方法对深度语义改写、长链工具组合和未知编码方式仍有限；clean case 数量还需扩大；后续可接入更细粒度权限模型和语义级检测。

## 13. Dashboard 答辩时重点展示什么？
先展示总览指标，再对比 baseline 和 full_guard，然后进入攻击类型分组，最后打开一个阻断案例，展示 context、tool_call、risk、decision 和 reasons。

## 14. 如何证明不是“只为样本写规则”？
样本覆盖多个载体、语言和工具类型；规则按照工具边界、数据流和策略矩阵设计，不绑定单个 case 文案。同时 evaluate 支持按多维元数据分组，便于扩展新样本验证。

## 15. 如果误报怎么办？
外发与写入类工具默认 ask 而不是全部 deny，保留后续人工确认空间。对于 public 读取和 final 回答，策略保持 allow，降低正常任务影响。
