## 1. Harness 的角色

`harness/` 是本项目的 AI 智能体控制平面，不是 Guard 产品源码，也不保存模型权重
或正式实验结果。它负责让后续智能体或开发者能够从仓库文件恢复：

- 要做什么；
- 哪些路径允许或禁止修改；
- 当前进度和阻塞是什么；
- 哪些失败已经发生、不能原地重试；
- 哪些验证通过；
- 什么证据可以或不可以进入论文。

根目录 `AGENTS.md` 是最高优先级工作协议。Harness 源码/状态只在 `harness/`；
项目运行逻辑继续位于 `m3_*`、`experiments/`、`protocols/`、`scripts/` 和
`tests/`。

## 3. 目录和所有权

| Harness 区域 | 内容 | 修改规则 |
|---|---|---|
| `config/` | 权限、政策、工作流 | 安全边界变化必须记录决策 |
| `docs/` | 架构、开发规则、决策、智能体指南 | 只记录 Harness 工程，不放产品实现 |
| `specs/` | 产品、技术、验收事实 | 与当前论文/工程范围保持一致 |
| `features/` | 功能状态台账 | 只有通过验收才能 verified |
| `tasks/` | 任务模板和任务记录 | 当前论文任务为 `m3-paper-upgrade.md` |
| `state/` | 当前任务、进度、失败、历史、移交、长期记忆 | 每次实质变更后同步；历史段落不删除 |
| `scripts/` | Harness 初始化/测试/验证入口 | 不放实验运行器 |
| `workspaces/` | Runpro 分析工作区 | 不是正式结果目录 |
| `tmp/` | 可再生临时文件 | 不保存唯一证据 |

项目输出属于 `outputs/`，冻结和准入属于 `protocols/`，不得为了“统一”搬入 Harness。

## 4. 状态文件怎么读

### `state/current-task.md`

顶部最新检查点是当前工作上下文；下面旧 PID、旧下一步动作是历史记录。
当前任务 ID 仍为 `M3-PAPER-001`。新接手人应在顶部追加本轮目标、允许/禁止路径、
验收和最新状态。

### `state/progress.md`

累计事实时间线。用于回答“做过什么”和复核验证命令，不应当作单一当前状态页。

### `state/failure-log.md`

失败根、症状、根因和恢复决定。Task Shield、Progent、CaMeL、IPIGuard 的失败必须
在新版本中处理，不能修改旧根目录或只补有利行。

### `state/session-handoff.md`

下一会话的最短恢复入口。它必须写明当前服务状态、最新报告、未完成项和下一安全
动作；如果与旧进度段落冲突，以顶部最新移交说明为准。

### `state/task-history.md`

任务级审计时间线。只追加，不用来覆盖当前事实。

### `state/memory.md`

长期可复用经验，例如 Windows PID 检查、冻结哈希、失败分母和指标语义。
不要写短期 PID 或秘密。

## 6. 证据和状态词

- `smoke`（冒烟）：最小运行资格；
- `preflight`（预检）：依赖、身份和协议准备；
- `qualification`（资格）：小面板工程资格；
- `diagnostic`（诊断）：根因或方向；
- `historical`（历史）：历史工程；
- `post-hoc`（事后）：看到结果后的修复；
- `formal`（正式）：绑定精确冻结和 manifest 的正式结果；
- `confirmatory`（确认性）：独立盲测与预注册范围内的证据。

Harness 文档不得把前六类自动改写为正式或确认性证据。

## 7. 失败恢复纪律

1. 保留失败标准错误、追踪记录、案例 manifest 和原始分母。
2. 分析失败属于代码、资源、传输、解析、模型输出还是数据。
3. 修改方法必须新建版本化运行时、冻结、协议和输出根目录。
4. 禁止在失败根目录中选择性重试或删除失败行。
5. 资格实验只决定工程是否扩展，不依据结果是否“好看”选择保留。
6. 正式准入只在覆盖完全、未解释失败为 0、哈希和分析器全部通过时执行。

## 8. 当前关键风险

- 旧 AgentDojo 适配器把 `security` 语义取反；新版本必须使用 official-v2。
- M3/CaMeL 的低 ASR 可能来自低 TCR 或过度阻断。
- Qwen3 8B 对 verifier/policy JSON 合约和多请求基线可能过弱。
- `q2_to_80_action_audit_v1` 是旧快照，当前执行动作以最新规划器为准。
- 大量输出未被 Git 跟踪，不能 clean；冻结文件不能为路径美化而改写。
- API Token 只在 ignored `config/project.local.env`，不得进入 Harness。
