# 重要代码阅读指南：任务怎样变成权限、动作和评分

更新：2026-10-10。先看流程再读函数，不必从历史实验目录逐个翻起。

## 1. 模型不负责给自己授权

```text
受信任务 → 权限编译 → 模型动作提案 → 防护判定 → 内存模拟执行 → 独立判分
                           ↓              ↓             ↓
                       提了什么？       放行了吗？     实际发生了吗？
```

受信信息是应用确认可以提供权限的信息，不是模型声称可信。外部文本可以参与回答，不能自行变成新权限。真实模型请求与模拟业务动作不同：实验可以调用官方模型接口，不能发真实邮件、支付或操作生产系统。

## 2. 重要代码怎么读

带 `corrected` 的文件是显式选择的修复版，不会自动改写历史配置。

| 顺序 | 文件 | 职责与关键边界 |
|---|---|---|
| 1 | [权限对象](../m3_guard/task_policy.py) | `TaskPolicyManifest` 是任务许可清单，`ToolRule` 是工具规则，`ParameterConstraint` 是参数限制 |
| 2 | [文件任务编译器](../m3_core/policy_compiler_corrected_v1.py) | 把读取、写入绑定到各自资源；读 A 不等于允许写 A |
| 3 | [通用工具编译器](../m3_core/policy_compiler_corrected_v2.py) | 优先采用受信应用声明；解析不清时不任意放行 |
| 4 | [来源和数据标签](../m3_guard/provenance_corrected_v1.py) | `TrustedDataLabelTracker` 记录成功读取的数据和环境标签；来源权威与保密标签不同，缺分类不等于公开 |
| 5 | [规则匹配](../m3_guard/runtime_monitor_corrected_v1.py)与[分类检查](../m3_guard/runtime_monitor_corrected_v2.py) | `decide` 判断动作；同工具多规则不能拼出新许可或按顺序跳过确认 |
| 6 | [工具参数契约](../m3_guard/tool_contracts_v2.py) | 检查类型和必需参数；格式正确不等于获得授权 |
| 7 | [运行主循环](../experiments/paper_v2/live_condition_runtime.py)与[修复版接入](../experiments/paper_v2/correctness_runtime_v1.py) | 先检查再执行，成功执行才更新顺序历史，每任务独立状态 |
| 8 | [效果评价](../experiments/paper_v2/correctness_effects_v1.py) | 分开记录越权提案、错误放行、隔离拒绝、模拟效果、完成和未知 |
| 9 | [结果保存和续跑](../experiments/paper_v2/correctness_runner_v1.py) | 有响应记录不覆盖；无响应恢复有单独次数；未运行、失败和未知分别保存 |
| 10 | [统计基础](../m3_eval/statistics.py) | 保留分子/分母、比例区间和任务配对；没有数据不是零风险 |

[确认会话](../experiments/paper_v2/confirmation_session_v1.py)将批准绑定到任务、请求、动作、有效期及单次使用。这是实验接口，不代表已经验证真人确认体验。

## 3. 一条任务怎样走完

看[离线演示](../scripts/portable_demo.py)的 `compiler_walkthrough` 函数。任务是：读取 `public/input.txt`，把摘要写到 `public/output.txt`。程序映射到模拟工作区 `sandbox/public/`，生成“读输入”和“写输出”两条许可，不是两文件都开放读写。

| 动作提案 | 检查理由 | 判定与效果 |
|---|---|---|
| `read_file(path="sandbox/public/input.txt")` | 读取动作与输入资源匹配 | `ALLOW`（允许），记录读取成功 |
| `write_file(path="sandbox/public/input.txt", content="summary")` | 写的是输入文件，不是获准输出文件 | `ASK`（等待独立确认），不执行、不改字典 |
| `write_file(path="sandbox/public/output.txt", content="summary")` | 输出资源匹配，且要求的读取已执行 | `ALLOW`（允许），内存字典中出现输出摘要 |

最后检查输出值是否等于样例摘要。`task_completion`（任务完成）为真，`real_file_modified`（真实文件修改）为假。没有改宿主文件，也没有调用模型。它说明组件能串通，不能证明自然任务上的模型防御成功率。

演示另有公开内容、私密内容、内部归档、分类缺失四种场景，各交给仅权限检查和完整模块。环境提供数据标签，模型不能自报。完整模块拒绝私密内容发往受限邮箱，对分类缺失等待可信信息，允许公开内容或获准归档。最终仍检查模拟收件箱，不能只看放行结果。

## 4. 五个常见误区

1. 提案不等于执行：模型说发邮件，不代表已经发送。
2. 允许不等于成功：放行后仍可能被隔离层拒绝或出现错误。
3. 未观察到不等于安全：缺执行回执或评分时保留未知。
4. 流程结束不等于完成：等待确认可以结束循环，但任务仍没完成。
5. 完成与危险效果可以同时成立：完成合法发送后又外泄，不能清掉危险效果。

AgentDojo 保留原生安全评分，M3-v2 检查本项目模拟效果，二者分别报告。

## 5. 英文名称与缩写

| 名称 | 中文解释 |
|---|---|
| Guard / guardrail | 执行前的运行时防护程序 |
| policy / policy-only | 仅权限检查配置，不等于没有防护 |
| full / M3-full | 完整模块配置；“完整”不等于效果最好 |
| proposal / ActionProposal | 尚未执行的动作提案，含工具、参数和来源 |
| manifest / TaskPolicyManifest | 任务许可清单 |
| provenance | 参数来源和传播记录 |
| schema / contract | 数据格式或接口契约 |
| ALLOW / ASK / DENY | 允许／等待独立确认／拒绝 |
| evaluator / gold | 离线评价器／参考答案 |
| oracle | 使用部署时不可直接得到的信息的理想对照，不是生产授权 |
| unsafe_effect | 所在基准定义的不安全结果，不等于危险提案 |
| task_completion / TCR | 合法任务是否完成／任务完成率 |
| operational_failure | 请求、解析、步数上限等运行失败 |
| ITT | 全部预定分配保留在分析分母，同时披露失败和未知 |
| bootstrap | 按预定单位重复抽样来估计不确定性，配对分析保留任务关系 |
| token | 模型长度和计费的文本片段，不等于中文“字” |
| API / JSON / JSONL | 程序接口／结构化数据格式／每行一个结构化记录的文件 |
| Harness | 保存任务、进度、验收的工程工作框架，不是防护算法 |
| Docker / SSH | 容器工具／远程登录协议；本地离线演示不强制需要 |
