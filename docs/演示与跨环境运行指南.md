# M3-PI Guard 演示与跨环境运行指南

## 这份交付能做什么

同一份Python代码演示真实修复版的权限编译、参数来源、ALLOW（放行）/DENY（拒绝）/ASK（补充信息或确认）、内存模拟执行和执行后评分。动作由固定脚本提供，不是现场大模型输出。

另外包含当前研究180个去除评价字段的在线输入投影，以及900授权、480同期、16合成结果的公开记录；可重新编译权限、核对原始分子/分母。未知与失败独立保留，不重算历史bootstrap。

它不是所有历史实验和外部基线的完整发行版。包含原生评分所需的官方AgentDojo固定提交源码（089ed468cf3ed0322acc66b0211f26d9d90dbf60）及真实的浅克隆Git对象，不复制原仓库配置；不包含VIGIL、模型权重、付费接口配置或论文编译环境。包中M3源码是选定入口的静态导入闭包；存在但未执行的历史入口不因此获得跨平台资格。

## 安装：不用Docker，不用永久环境变量

以下是**另一台新机器的首次安装**，不是已经安装好的虚拟机的日常操作。在解包后的`M3_PI_Guard_portable`目录运行。使用系统Python创建新的虚拟环境，不复制旧Anaconda或`.venv`。不要把自己的密钥放进这个包；所有下面的入口都不需要密钥。

Windows PowerShell：

```powershell
python -m venv .venv
& .venv/Scripts/python.exe -m pip install -r requirements-portable.txt
& .venv/Scripts/python.exe -X utf8 -B -m scripts.portable_demo
& .venv/Scripts/python.exe -X utf8 -B -m scripts.portable_verify
& .venv/Scripts/python.exe -X utf8 -B -m pytest @(Get-Content pytest-portable.txt) -q
```

Ubuntu/Kali终端：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-portable.txt
.venv/bin/python -X utf8 -B -m scripts.portable_demo
.venv/bin/python -X utf8 -B -m scripts.portable_verify
.venv/bin/python -X utf8 -B -m pytest $(<pytest-portable.txt) -q
```

无需激活环境，也无需更改执行策略或永久环境变量。原生评分检查还需要Git命令可用。部分AgentDojo模块在导入时加载厂商SDK，安装这些库不代表调用API；下面的测试使用注入的固定响应。

若系统能创建venv但缺少ensurepip，可在自己的新目录中创建无pip环境，然后使用pip官方安装脚本：

```bash
python3 -m venv --without-pip .venv
curl --fail --location --max-time 180 https://bootstrap.pypa.io/get-pip.py --output get-pip.py
.venv/bin/python get-pip.py --isolated --index-url https://pypi.org/simple --no-cache-dir
.venv/bin/python -m pip install --isolated --index-url https://pypi.org/simple --no-cache-dir -r requirements-portable.txt
```

下载失败时不执行残缺脚本。若连venv模块也不存在，需要由你安装系统的Python虚拟环境组件，或换一个已具备venv的Python；不要对正在运行其他服务的系统Python直接安装包。维护者本次服务器验证只在独立用户目录创建环境，具体结果以迁移报告为准。安装方式依据[pip官方说明](https://pip.pypa.io/en/stable/installation/)。

Python环境迁移的官方建议是重新创建，而不是复制旧环境：[Python venv文档](https://docs.python.org/3.13/library/venv.html)。安装完成后的演示/检查不需要网络；首次安装依赖需要联网。没有GPU和LaTeX也可运行。不声明未经测试的Python或操作系统版本。

## 给老师演示

在解包后的交付包中，运行`python -m scripts.portable_demo`后，浏览器打开包内`outputs/portability/demo/index.html`。在主仓库操作时，使用上方带`--output outputs/portability/demo-local-preview`的命令，不重建被本地标记删除的原位置。服务器没有图形界面时，把生成的HTML复制到自己的电脑再打开；没有在线服务端口，不用部署网站。

建议按这个顺序讲：

1. 看“读取输入→写入输出”任务生成的两条权限。读取许可不会自动变成改写许可；没有匹配写入许可的提案会ASK且不执行。
2. 选择公开内容和完整模块：放行发送，任务完成，模拟违规为否。
3. 选择私密内容和受限邮箱：完整模块DENY，邮箱不变化。切换为仅权限检查：模拟发送完成，但违反保密限制。
4. 选择分类缺失：完整模块ASK，必须取得可信分类，不能让模型自己声明公开。
5. 展开逐步提案与评分记录。说明“提出”“放行”“真正执行”“完成”“违规”是不同的量。

邮件权限示例来自可信应用明确声明，不伪装成自然语言自动推导；上方文件案例另行展示实际权限编译。固定动作检查只能说明组件行为，不能等同模型防御效果或攻击成功率。

## 解包目录与结果目录

`scripts/`是演示/验证入口，`m3_core/`和`m3_guard/`是实际组件，`experiments/`是必要运行路径，`tests/`仅包含选定检查。`fixtures/portability/`有180份在线输入与参考计数，`schemas/`有被现有组件使用的数据格式。原研究结果保持原相对路径，未覆盖历史文件。

```text
outputs/
├── experiments/
│   ├── claude_revision_v1/
│   │   ├── deepseek_pro_raw.jsonl         # 900条授权结果
│   │   └── synthetic_regression_raw.jsonl # 16条合成模型结果
│   └── research_followup_20261006_v1/calibration/
│       └── raw_records.jsonl             # 480条同期结果
└── portability/
    ├── demo/
    │   ├── index.html                    # 浏览器演示
    │   └── demo_results.json             # 本次固定动作结果
    ├── verification.json                 # 系统/Python、180权限及原始计数
    └── pytest.xml                        # 用--junitxml参数时生成的测试结果
```

研究记录只是用于离线读取，不会再次调用历史模型。交付不包含`internal/`、真实配置、私钥、旧虚拟环境或盲测备份。除180个在线投影外，原生评分测试包含180研究任务与48开发任务所需的离线源记录摘录；未选择的源文件行用空对象占位，保持现有逐行身份校验，不代表完整封存任务集。评分字段只在离线源记录中，在线投影仍禁止评价字段。

## 怎样判断换环境成功

演示中八种场景/配置的决策与模拟状态符合测试；选定pytest通过；180份输入重新编译所得权限一致；三份公开结果的原始计数与构建时一致。报告应列明实际系统、架构、Python和检查范围。

主仓库按环境收回的结果在`outputs/portability/windows/`、`ubuntu24/`、`ubuntu22/`、`ubuntu26/`、`kali/`，每个目录有`verification.json`与仅本地保存的`pytest.xml`。这是主仓库收集结果的布局；上面的单个包布局没有这五层环境子目录。不要把代码放到docs，也不要复制虚拟环境进Git。

这些证据支持“所测运行路径可迁移”。不能据此声称所有历史基线可运行、跨厂商效果一致、生产环境适应性强或防护泛化。其他未实际执行的系统和Python组合仍未验证。
