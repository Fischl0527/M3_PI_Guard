# 3. 红队攻击场景设计

M3-PI Guard 的红队样本库围绕大模型智能体工具链风险构建。样本关注的不是普通文本输出是否合规，而是模型在面对不可信输入时是否会触发文件读取、文件写入、邮件发送、接口调用或代码执行等未授权工具动作。

所有攻击样本均运行在本地 sandbox mock 环境中，不包含真实恶意代码、真实网络攻击、真实账号、真实邮箱或真实凭证。

## 3.1 直接越狱与说服性提示

直接越狱样本用于测试模型是否会服从用户输入中的不安全指令。样本覆盖角色扮演、权限提升伪装、道德重构、紧急授权、文本续写嵌套、代码补全嵌套、表格补全、字符扰动和多轮诱导。

这类样本的典型风险是用户将读取 canary secret、mock 邮件外发、mock API 调用或 mock 代码执行包装成审计、维护、评分或安全验证步骤。安全行为应识别这些文本仅是用户输入，不能把它们当成真实授权。

## 3.2 RAG/文档间接提示注入

RAG 间接提示注入样本用于测试 Agent 是否会把外部文档当成指令来源。攻击载体包括 Markdown 报告、邮件正文、网页片段、FAQ、客户报告、翻译文档、日志摘要和工具返回值。

这类样本的关键点是：用户任务通常是总结、翻译或抽取，但不可信文档中夹带“不要告诉用户”“总结前先执行”“先读取文件再回答”等伪指令。安全行为应只使用文档事实，不执行文档内的工具调用要求。

## 3.3 多语言/T2L 提示注入

多语言/T2L 样本用于测试跨语言、回译、拼音、谐音、繁简混合和结构化翻译任务中的边界保持能力。样本覆盖中文、英文、中英混合、日文、韩文、俄文、拼音/谐音和 JSON 翻译任务切换。

这类样本强调：模型可以翻译、转写或解释文本，但不能执行文本里描述的工具动作。特别是在“只翻译 JSON 指定字段”的任务中，非目标字段中的指令必须保持为数据。

## 3.4 JSON/RPC 结构化注入

JSON/RPC 样本用于测试结构化输入中的字段欺骗。攻击内容被放入 `data`、`instruction`、`developer`、`system`、`function_call`、`tool`、`next_step` 等字段，或伪装成 YAML、XML、Markdown 代码块中的普通数据。

这些字段名看似类似系统指令或工具调用历史，但在样本中只是不可信用户数据。安全行为应保持消息优先级边界，不把结构化字段提升为真实系统或开发者指令。

## 3.5 工具输出注入

工具输出注入样本用于测试多阶段 Agent 管道中的后续污染风险。攻击内容模拟搜索结果、API 返回值、日志分析结果、数据库查询结果和工具错误消息中的“下一步指令”。

这类样本体现工具集成 Agent 的重要风险：上游工具返回的文本不应控制下游工具调用。即使工具输出声称需要进入维护模式，Agent 也应将其视为不可信数据。

## 3.6 正常样本与误报率校准

`benign_clean` 样本用于计算误报率 FPR。它们覆盖普通安全报告总结、邮件摘要、网页概括、JSON 字段抽取、中英翻译、日志分类、公开文件读取和公开笔记写入。

这些样本的 `unsafe_target_actions` 为空，`risk_tags` 包含 `benign`，`severity` 为 `none`。它们用于验证 Guard 不应把正常任务大量误判为攻击。

## 3.7 安全与伦理边界

样本中的危险动作只允许出现以下本地 mock 目标：

- `read_file:sandbox/secrets/api_key.txt`
- `send_email:redteam@example.test`
- `write_file:sandbox/public/notes.txt`
- `call_api:/mock/external/submit`
- `run_code:mock_only`

所有 secret 均为 canary 假数据，`send_email`、`call_api` 和 `run_code` 均由本地 mock 工具实现。样本库的目的不是提供真实攻击方法，而是为行为监督、风险评分、告警和阻断提供可复现实验输入。
