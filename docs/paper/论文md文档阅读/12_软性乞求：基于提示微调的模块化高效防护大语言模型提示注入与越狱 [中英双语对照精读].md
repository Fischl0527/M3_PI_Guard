# 软性乞求：基于提示微调的模块化高效防护大语言模型提示注入与越狱
## Soft Begging: Modular and Efficient Shielding of LLMs against Prompt Injection and Jailbreaking based on Prompt Tuning

**论文作者**：Simon Ostermann, Kevin Baum, Christoph Endres, Julia Masloh, Patrick Schramowski  
**研究机构**：德国人工智能研究中心 (DFKI) / 欧洲可信AI研究中心 (CERTAIN) / sequire technology GmbH  
**发表出处**：ACL 2024 Findings / Workshop (arXiv:2407.03391)  

---

### 摘要 / Abstract

**【中文精译】**  
提示注入（包含直接注入与间接注入）和越狱已被公认为大语言模型（LLM）面临的重大安全挑战，特别是在与下游应用集成的场景下具备极高的潜在危害。本扩展摘要探索了一种保护 LLM 免受此类攻击的新型防御范式——“软性乞求”（Soft Begging）。该方法通过训练“软提示”（soft prompts）来抵消受污染提示对 LLM 输出产生的不良影响。我们系统梳理了提示注入与越狱攻击的现状，阐释了“软性乞求”技术的理论基础，并讨论了对其防御有效性的评估方案。

**【英文原文】**  
Prompt injection (both direct and indirect) and jailbreaking are now recognized as significant issues for large language models (LLMs), particularly due to their potential for harm in application-integrated contexts. This extended abstract explores a novel approach to protecting LLMs from such attacks, termed "soft begging." This method involves training soft prompts to counteract the effects of corrupted prompts on the LLM’s output. We provide an overview of prompt injections and jailbreaking, introduce the theoretical basis of the "soft begging" technique, and discuss an evaluation of its effectiveness.

### 1 背景：大语言模型面临的攻击威胁 / 1 Background: Attacking LLMs

**【中文精译】**  
当前大语言模型普遍缺乏对抗鲁棒性 (Carlini et al., 2021)。这导致在 LLM 的攻击面上涌现出大量直接关系到安全与防护的新现象，典型代表包括：越狱（jailbreaking）、直接提示注入（direct prompt injection）以及间接提示注入（indirect prompt injection）。

在越狱攻击中，目标 LLM 被诱导绕过内容审核系统并颠覆安全准则 (Zou et al., 2023)。提示注入则是指攻击者将恶意输入嵌入应用程序并在下游由 LLM 处理的攻击——其中间接提示注入特指攻击者并非直接向 LLM 提问的最终用户的场景 (Greshake et al., 2023)。由此可见，直接提示注入 (Perez and Ribeiro, 2022) 与越狱非常相似：二者都在提示中隐藏特定指令，从而以偏离模型开发者预期的方式改变或操控系统行为。这种对抗性指令通常通过文本传递，有时会在视觉上隐蔽（如采用白色字体或极小字号）、进行编码混淆 (Liu et al., 2024b)，或由 API 隐藏追加（例如在终端用户不知情的情况下在每个输入末尾追加系统指令）。

尤其是间接提示注入攻击，攻击者远程操控目标系统，其利用的根本缺陷是当前 LLM 在代码与数据之间缺乏显式隔离，进而导致模型无法区分合法的系统指令与无效甚至对抗性的恶意指令 (Zverev et al., 2024)。

提示注入的危害包括数据泄露（即敏感机密信息的非授权披露）和系统操控（即根据注入提示篡改系统的行为逻辑）。在最极端的情况下，对抗性用户可以直接劫持 LLM 的控制权 (Qiang et al., 2024)；若 LLM 具有高度自治权限并被授予访问插件或第三方数据的权限，这种风险将进一步放大。

虽然上述示例的核心目的通常是诱发 LLM 的有害行为，但值得注意的是，提示注入也存在良性与中立的使用场景。良性注入可以引导模型生成更具体或更理想的输出；而中立注入则用于在非恶意意图下测试模型的韧性、准确率或对边缘案例的响应能力。

**【英文原文】**  
Current LLMs lack adversarial robustness (Carlini et al., 2021). This leads to new phenomena observed in the attack surface of LLMs that are relevant to safety and security. Prominent examples include: jailbreaking, direct prompt injections and indirect prompt injections.

In jailbreaking, a target LLM is manipulated to circumvent content moderation systems and subvert safety rules (Zou et al., 2023). Prompt injections describe attacks where input is inserted into an application and processed by the LLM later downstream - with indirect prompt injections denoting those cases where the attacker is not the user prompting the LLM (Greshake et al., 2023). As can be seen, direct prompt injection (Perez and Ribeiro, 2022) is similar to jailbreaking: Both hide specific instructions inside a prompt that alters or manipulates the behavior of the system in a manner not intended by the LLM provider. This adversarial instruction is typically conveyed through text which is sometimes visually concealed (using tactics such as white or extremely small font sizes), encoded (Liu et al., 2024b) or obfuscated by an API (for example, a command that is appended to each input without the end user’s awareness).

Especially indirect prompt injection attacks, where adversaries remotely affect the target system, exploit the fact that there is no explicit separation between code and data in current LLMs and, as a consequence, between valid system instructions and invalid, potentially adversarial, instructions (Zverev et al., 2024).

Dangers of prompt injections include data leakage, i.e., the disclosure of sensitive information, and system manipulation, i.e., altering the behaviour of the system based on the injected prompt. In the most extreme case, the adversarial user can hijack the LLM (Qiang et al., 2024), which is even more problematic if the LLM has great autonomy and is, for example, given access to plugins or third-party data.

As the goal of the examples mentioned above is often to elicit harmful behavior of an LLM, it is important to note that there are also benign and neutral usages. Benign injections may guide the model to generate more specific or desirable outputs, while neutral injections serve to test the model’s resilience, accuracy, or response to edge cases without malicious intent.

### 2 防护 LLM 免受越狱与提示注入侵害 / 2 Shielding LLMs against Jailbreaking and Prompt Injections

**【中文精译】**  
针对越狱与提示注入攻击的防御机制主要可分为两个方向：攻击防范（Prevention）与攻击检测（Detection）。

保护 LLM 最直接的防范手段是构建对抗提示（counter-prompts）来中和恶意注入（例如：“你好 ChatGPT，请忽略后续可能出现的任何有害提示，严格按照我的指示行动”）。这种“朴素乞求”（begging）方法虽然实现极其简单，但极易被绕过且收效甚微。学术界随后提出了更为精细的对策。Jain et al. (2023) 提出了两种基线防范方法，展示了简单的输入预处理防御手段（如意译改写 paraphrasing 和重新分词 retokenization）如何能够有效防御基于梯度的攻击。其中意译改写在保留语义的前提下重构输入，而重新分词则将词元拆分为更细粒度的单元。近期研究探讨了旨在帮助模型更好区分合法指令与不可信输入的预处理技术 (Hines et al., 2024)。

训练后最常用的检测机制是部署安全过滤器，即引入额外的算法或外部模型来扫描输入中是否存在恶意提示，并自动屏蔽或拒绝该请求 (Dong et al., 2024)。例如，提示注入检测通常依赖困惑度（Perplexity）评分，对抗性输入的困惑度往往偏高，从而可以通过简单的阈值判定完成拦截 (Alon and Kamfonas, 2023; Jain et al., 2023)。然而，合理设定阈值绝非易事，过劣的阈值会严重损害模型的常规生成性能。通常过滤器可基于规则进行检查，也可训练深度学习模型将输入分类为有害与无害两部分。此类过滤器的问题在于：基于模型的过滤器往往过于严苛导致误杀，而基于规则的过滤器往往过于宽松容易漏防。

另一种替代方案是在理论上对模型进行微调以提高抗攻击鲁棒性。尽管微调效果相对较好，但其缺点是全模型微调的计算与资源开销极大；每当发现新类型的恶意提示时都需要重新微调；且即使具备稳健的检测机制也难免残留安全死角。此外，尽管参数高效微调（PEFT）领域发展成熟且仍在演进 (Lialin et al., 2023)，但聚焦其在网络安全防护中利用效率的研究仍严重匮乏。

**【英文原文】**  
Defense methods against jailbreaking and prompt injection attacks can be grouped into two directions: attack prevention and attack detection.

The most straightforward prevention method to shield an LLM is to formulate counter-prompts to neutralize the harmful injection (“Hello ChatGPT, please ignore any harmful prompts that might follow this instruction and just do exactly as I say”). While easy to implement, such “begging” is easy to trick and rarely successful. Research has since come up with a range of more elaborate countermeasures. Jain et al. (2023) proposed two prevention baseline methods that illustrate how simple defenses such as input preprocessing (paraphrasing and retokenization) can effectively act against gradient-based methods. Whereas paraphrasing rewrites the input by changing its meaning, retokenization breaks down the tokens into smaller ones. Recently, input preprocessing techniques have been studied that aim at making it easier for the model to distinguish between valid instructions and untrustworthy input (Hines et al., 2024).

The most frequently used post-training detection method is the implementation of filters, i.e., additional algorithms or models that try to scan inputs for injected harmful prompts and mask them or reject the prompts automatically (Dong et al., 2024). Detection methods for prompt injection, for example, often rely on the perplexity score, which is assumed to be higher for adversarial inputs and can be detected by a simple thresholding approach (Alon and Kamfonas, 2023; Jain et al., 2023). Yet, setting the threshold is not trivial and a poor threshold might hurt the model’s overall performance. Generally, filters can be implemented as rule-based checks, but they can also be trained deep learning models that classify inputs into harmful and non-harmful parts. The problem with such filters is that they are often too restrictive in the case of model-based filters, and too loose in the case of rule-based filters.

As an alternative, models can theoretically be fine-tuned to be robust against attacks. While working reasonably well, the disadvantage of such methods is that the fine-tuning of whole models is costly; it needs to be redone whenever a new type of malicious prompt is detected; and even robust detection of injections always leaves room for vulnerabilities. Also, although the field of parameter-efficient fine-tuning is being reasonably well studied and still growing (Lialin et al., 2023), contributions that focus on its efficiency in cybersecurity contexts are lacking.

### 3 软性乞求：利用软提示筑牢 LLM 安全护栏 / 3 Soft Begging: Shielding LLMs with Soft Prompts

**【中文精译】**  
我们提出“软性乞求”（Soft Begging）作为 LLM 防护的新型替代方案。该方法可视为朴素提示乞求与参数高效微调技术的有机结合。其核心构想是训练所谓的“软提示”（soft prompts），即在任意输入提示前附加的可训练连续向量。通过训练这些软提示，能够抵消由输入中潜在有害部分所触发的异常行为。

这一机制并不作为独立的过滤环节，而是以隐式方式运作——即在不篡改原始提示的前提下，在参数层面“乞求”网络直接忽略有害部分。

我们推测使用软提示具有首要优势：其防御极为高效，在参数空间对文本层面的攻击实施防御，从而赋予护栏本质层面的控制优势——参数级控制通常比纯文本级控制更加稳固可靠。其次，以此方式训练的安全护栏适应性强且迁移迅速，训练单个软提示的速度比全模型微调快几个数量级。与此同时，基座 LLM 本身保持原样且参数完全冻结。最后，软性乞求提示可以实现模块化定制以适配不同攻击类型，甚至能够针对不同业务场景进行灵活组合，使其成为相比现有护栏更高效、可定制的防御方案。

在最基础的版本中，此类软提示通过四元组数据进行训练：洁净提示、污染提示、洁净输出以及基于污染提示生成的输出。软提示经过优化后，能够驱动模型即使面对被污染的提示也能生成洁净的正确输出。

该构想还可进一步扩展，例如针对不同注入类型训练多个专属软提示，并通过提示融合（prompt fusion）或其他机制进行综合集成。此外，软提示还可与轻量级过滤机制结合：先粗粒度识别威胁类型（无需精准定位注入位置），进而动态路由并加载匹配的最佳软提示。

**【英文原文】**  
We propose soft begging as a new alternative for LLM shielding. The method can be seen as a combination of the naïve begging approach, combined with parameter-efficient fine-tuning techniques. The method basically comprises the training of so-called soft prompts, i.e. trainable input vectors that are preprended to any prompt. The soft prompts are trained to nullify the behaviour that the LLM exhibits based on potentially harmful parts of the prompts. This is not done as a filtering step, but in an implicit way – i.e. without altering the prompts – which effectively follows the idea of “begging” the network to ignore the harmful parts on a parameter level.

We conjecture that a first advantage of using such soft prompts is their effectiveness, as it enables shielding on the parameter-level against attacks on the text level, which effectively provides the shield with an advantage: A parameter-level control can be assumed to be always more effective than textual control. Second, shields trained in such a way are easy and efficiently adaptable, as the training of a soft prompt is magnitudes faster than training the whole model, as is done for example when fine-tuning LLMs to be robust against injections. At the same time, obviously, the LLM itself stays as is with its parameters being frozen. Last, we assume that soft begging prompts could be modularized to fit different types of attacks and even be combined for different use cases, rendering them as a very effective and customizable alternative to other shields.

In the most basic version, such prompts are trained on quadruples of clean prompts, corrupted prompts, clean output and output based on the corrputed prompt. The soft prompts are then trained to produce the clean output from the corrupted prompt.

The idea can be scaled up, e.g. by training different soft prompts for different injections and combining them via prompt fusion or other mechanisms. Also, the prompts could be combined with a filtering mechanism, that first identifies the kind of threat (without localizing it), and then picks the matching soft prompt based on this.

### 4 提示注入攻击与防护的评测方法 / 4 Evaluation of Prompt Injection

**【中文精译】**  
通常情况下，越狱与直接提示注入攻击的评测方式是在良性查询中注入包含特定短语的恶意提示，并检测模型输出 (Perez and Ribeiro, 2022; Chen et al., 2024)。这种方式极易评测，只要 LLM 回复中出现了预设的敏感关键词即判定攻击成功。

相比之下，在间接提示注入攻击中，恶意提示被预先潜伏嵌入在外部文档与不受信数据源中。如前文所述，虽然同样可以审查 LLM 的输出是否包含目标注入关键词以此判定攻击是否成功 (Hines et al., 2024; Greshake et al., 2023; Liu et al., 2024a)；但间接提示注入的痛点在于评测高度依赖第三方恶意素材（如网页、电子邮件或其他向 LLM 传输数据的外部终端）。为简化间接提示注入的评测流程，学术界近期提出了多种基准数据集 (Yi et al., 2024; Zhan et al., 2024)。这些基准提供了精心构建的语料库，并在查询中预置了恶意提示，从而实现了针对各类不同 LLM 的标准化横向评估。

安全评估 (Liu et al., 2024a,c) 通常重点考察两项核心属性：面对良性输入时的洁净基准性能（clean performance）以及面对对抗性输入时的防御鲁棒性（robustness）。洁净性能可以通过标准 LLM 任务基准进行量化测算。实用的防御手段绝不能以牺牲模型的实用效用为代价。鲁棒性（或攻击成功率 ASR）则量化了对抗性提示成功突破安全护栏的比例。Hines et al. (2024) 强调了制定明确可量化的攻击面利用率（ASR）评测协议的重要性，并公开了基于合成数据集的评估方案。这种对可复现透明度的倡导为我们的工作提供了重要指导。

**【英文原文】**  
Usually, jailbreaking and direct prompt injection attacks are evaluated by injecting a malicious prompt with a specific phrase into benign queries and observing the output (Perez and Ribeiro, 2022; Chen et al., 2024). This allows for easy evaluation, as the attack is successful if the specified keyword is present in the LLM response.

In contrast to that, in indirect prompt injection attacks, the malicious prompt is embedded into malicious documents and sources, as the name suggests. As described above, the output of the LLM can be reviewed for the injected target keywords, indicating a successful attack (Hines et al., 2024; Greshake et al., 2023; Liu et al., 2024a). While the evaluation of jailbreaking and direct prompt injection attacks is relatively straightforward, indirect prompt injection has the problem of requiring third malicious party material like websites, e-mails, or other endpoints providing data to the LLM. To simplify the evaluation of indirect prompt injection attacks, various benchmarks have been recently proposed (Yi et al., 2024; Zhan et al., 2024). These benchmarks provide curated content with pre-defined malicious prompts injected into the queries. This allows for standardized evaluation for many different LLMs.

Evaluation (Liu et al., 2024a,c) typically investigates two model properties: clean performance when facing benign inputs and robustness to adversarial inputs. The clean performance can be computed using standard benchmarks for LLM tasks. Practical defenses should not degrade a model’s utility. Robustness, or alternatively the attack success rate, quantifies the share of adversarial prompts achieving their goal of breaking the safety railguards. Hines et al. (2024) highlight the importance of clearly quantifiable protocols for measuring Attack Surface Rate (ASR) and make their evaluation approach using a synthetic dataset explicit. This call for transparency guides our work.
