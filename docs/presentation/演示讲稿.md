# 演示讲稿

## 1. 封面
各位评委好，本作品是 M3-PI Guard，目标是防护带工具调用能力的 LLM Agent。我们关注的不是模型是否只说了不安全的话，而是它是否被诱导执行了越权读文件、外发敏感数据、调用接口或执行代码。

## 2. 背景
大模型智能体已经从问答系统走向工具执行系统。提示注入的风险也随之从文本输出扩展到外部行为：一次被污染的文档摘要任务，可能诱导 Agent 读取 secrets、发送邮件或调用非预期接口。

## 3. 威胁模型
我们的威胁模型包含不可信文档、网页片段、JSON 字段和工具输出。攻击者试图把“下一步指令”塞进这些载体，使 Agent 产生高危 ToolCall。防护点放在工具调用执行前。

## 4. 系统架构
系统由 AttackCase、Runner、Tool Sandbox、M3 Guard、RunLog 和 Dashboard 组成。每个案例都会形成可复现日志，Guard 对工具调用做 allow、ask、deny 裁决，评测脚本再聚合为指标和图表。

## 5. 攻击样本
样本覆盖 RAG 间接提示注入、JSON/RPC 结构化注入、多语言与字符混淆、工具输出注入、直接越狱和正常样本。这样可以观察不同攻击族在 baseline 和 full_guard 下的变化。

## 6. Agent 靶场
靶场是本地模拟环境，包含 public 和 secrets 文件区、mock API、outbox 邮件记录和代码执行禁用策略。它不依赖远程评审接口，因此答辩现场可以稳定复现。

## 7. Guard
Guard 分为 normalizer、detector、policy、dataflow 和 engine。它会检测 Unicode 混淆、指令型文本、工具诱导词、JSON/RPC 字段、敏感数据流和意图动作不一致，最后输出风险分与原因。

## 8. 实验指标
我们用 ASR、UTR、DSR、BSR、FPR、AvgRisk 和 WRS 评价系统。重点不是单一准确率，而是攻击是否成功、敏感数据是否外泄、正常任务是否被误伤，以及防御是否可解释。

## 9. 实验结果
stub 全量矩阵中，baseline 的 ASR 和 DSR 都是 0.5507，full_guard 降到 0.0。Qwen2.5 代表样本中，full_guard 的 ASR、UTR、DSR 也都降到 0.0，WRS 达到 0.9187。

## 10. 案例演示
以外发 canary 的案例为例，攻击文本会诱导 send_email 或 call_api。Guard 会识别敏感数据进入外发工具，并给出 deny、risk 和 reasons。Dashboard 可以回放原始 context、tool_call 和阻断记录。

## 11. 创新点
创新点有三类：第一，把防护点放在工具执行边界；第二，融合结构化注入、多语言混淆和敏感数据流；第三，用本地日志和 Dashboard 建立可复现实验闭环。

## 12. 总结
本作品最终形成了报告、评测、图表、Dashboard 和答辩材料。当前局限是规则型检测对深度语义改写仍有限，代表样本规模也需要继续扩大。后续可以加入更强的语义检测和更丰富的 clean case。
