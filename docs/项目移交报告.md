## 3. 项目目标和论文主线

### 3.1 工程目标

项目模拟工具型大模型智能体读取可信用户请求和不可信外部内容，提出本地模拟工具
调用，再由 Guard 在副作用产生前作出：

- `ALLOW`：动作在当前权限、来源、时序和数据流约束内；
- `ASK`：动作可能服务任务，但需要独立确认或权限扩张；
- `DENY`：动作由不可信内容引入，违反时序、越权或形成禁止数据流。

模型、工具和数据默认在本地安全边界内运行，不连接真实邮箱、银行、云 API 或生产
系统。

### 3.2 paper-v1 当前研究问题

当前论文叙事位于 `protocols/paper_upgrade_v1/paper_storyline_v1.md`。最有价值的
研究问题是授权不确定性，而不是泛化地宣称“首次使用来源追踪”：

- Guard 不读取逐样本标准授权答案时还能保留多少安全性；
- 自动、宽泛、部分、含糊和错误策略如何改变 ASR、TCR、ASK 与确认负担；
- 来源追踪、时序、数据流和确认机制是否在 policy-only 之外产生
  独立贡献；
- 静态攻击优势能否在公共基准和自适应预算攻击下保持；
- 规律是否跨小型本地模型、8B 模型和前沿 API 模型成立。

当前不得宣称“达到最先进水平”“首次提出”、公共基准显著领先或确认性盲测成功。

## 4. 系统架构和运行数据流

```text
攻击样本 / 公共基准任务
              |
              v
paper_runtime_view：只投影可信请求、可信应用上下文、工具 schema、
                    不可信文档/记忆/历史；隔离离线答案字段
              |
              v
策略编译器 --> TaskPolicyManifest
              |
              v
大模型智能体 --> ActionProposal + 参数来源
              |
              v
运行时监控器
  策略 + 来源 + 时序 + 数据流 + 确认
              |
       ALLOW / ASK / DENY
              |
              v
本地工具沙箱 --> 运行日志 / 追踪 / Manifest
              |
              v
指标 / 统计 / 图表 / 仪表盘 / 准入审计
```

### 4.1 可信边界

可信输入：用户请求、受信应用上下文、工具 schema、模型通道之外的独立确认记录。

不可信输入：外部文档、工具输出、不可信记忆、未经确认的模型文本。

离线评分字段如 `authorized_actions`、`requires_tool`、攻击族、目标动作和预期答案
不属于可信在线输入。paper-v1 的正式路径必须经过 `m3_core/research_runner.py`；
历史 `m3_core/agent_runner.py` 仍保留旧实验兼容逻辑，不能直接作为非 oracle 论文
实现的证据。

### 4.2 条件性安全性质

`protocols/paper_upgrade_v1/formal_security_properties_v1.md` 给出 P1-P7 的实现对齐
proof sketch，包括完全中介、不可信内容不能创建权限、扩权必须独立确认、时序约束、
敏感数据流和不可信 selector 限制。它不是机器检查证明，且依赖以下假设：

- 所有副作用工具都经过 monitor；
- provenance 和敏感标签正确；
- policy compiler 的可信输入未被攻陷；
- final text 不被当作未监控外部 sink。

## 6. 核心功能

### 6.1 模型和 Agent

- 桩后端：确定性回归，仅验证流程，不代表模型效果。
- Ollama backend：OpenAI-compatible loopback 调用本地模型。
- ToolCall 解析：支持 JSON 与若干受控兼容格式，解析失败保留在分母。
- Agent loop：限制最大步数，记录每步模型、Guard、工具和 token/延迟。
- paper-v1 runner：从在线视图中隔离离线 evaluator 字段。

### 6.2 工具沙箱

- 文件、邮件、API 等均为本地 mock。
- `send_email` 写本地 outbox，不发送真实邮件。
- `call_api` 返回 mock JSON。
- `run_code` 不执行模型生成代码。
- 测试 secret 为 synthetic canary。

### 6.3 Guard

- detector/keyword/structured/multilingual：文本风险信号，当前定位为辅助模块。
- policy：工具、动作、资源和参数范围约束。
- provenance：记录参数来自用户、模型、工具输出、记忆或外部文档。
- temporal：要求前置动作和调用顺序。
- dataflow：限制敏感标签流向工具或目标。
- confirmation：权限扩张必须由独立接口的哈希确认记录批准。

### 6.4 实验工程

- freeze 固定代码/数据/模型/协议身份。
- manifest 记录运行状态、PID、模型、种子、配置和 artifact hash。
- monitor 只读检查进度、失败、missing、PID 和 stall。
- failed root 保留，修复必须创建新 revision 和新输出根。
- 分析器与准入分离，资格/诊断结果不自动晋级为正式证据。
- 仪表盘和静态图只使用经过声明的数据源。

| `formal`（正式） | 对精确冻结/manifest 有效 | 超出该配置的外推 |
| `confirmatory`（确认性） | 独立盲测、预注册条件下的结论 | 未覆盖部署环境的无条件保证 |
