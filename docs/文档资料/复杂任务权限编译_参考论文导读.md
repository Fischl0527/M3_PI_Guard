## 1. Progent：生成权限与控制更新分开

完整题名为 *Progent: Securing AI Agents with Privilege Control*，即“通过权限控制保护AI智能体”。旧题名 *Programmable Privilege Control for LLM Agents* 属于早期版本。

重点读4.3、5、6节：模型从用户任务生成工具/参数规则，运行中提出更新，SMT求解器检查许可动作集合是否扩大。SMT是验证逻辑条件的软件；新许可集合只是旧集合的子集时可自动更新，否则须批准。

M3借鉴点：模型起草、程序检查、限定权限更新；通用硬限制不能被任务规则覆盖。形式保证是未经批准不扩权，不保证初始自然语言解释正确。其主实验自动批准扩权的设置不作为本项目部署建议。

## 2. PACT：分别检查收件人与正文

完整题名为 *The Granularity Mismatch in Agent Security: Argument-Level Provenance Solves Enforcement and Isolates the LLM Reasoning Bottleneck*。PACT指“来源感知能力契约”，不是同名的其他协议或合规测试。

重点读3.2–3.4节与附录C：目标、命令、凭据、内容等参数承担不同角色。网页可以提供邮件正文，但不能自行指定收件人；组合后的值保留来源，认证只对限定参数/用途有效。

M3借鉴点：参数角色、后端核验、跨步骤来源和内容流，避免整次调用一概阻断。论文也承认自动角色判别和来源推断会错；正确契约/来源前提下的机制保证不等于自动部署表现。

## 3. AgentSpec：使用已有语义检查函数

题名意为“面向安全可靠大语言模型智能体的可定制运行时执行约束”。重点读3节、5.3节及讨论：规则由触发条件、检查和处置构成，生成器结合工具说明、已有检查函数和示例。

M3借鉴点：把复杂任务翻译为有限、可测试的谓词，而不是执行模型生成的任意代码。同时测危险动作漏拦与正常动作误拦；格式正确或与示例相似不能代替语义正确。

## 4. CaMeL：计划与外部内容分离

完整题名 *Defeating Prompt Injections by Design*，即“通过设计击败提示注入”。重点读5节、9节：可信规划与隔离内容处理分开，解释器追踪变量依赖，在工具执行前检查参数和数据流。

M3借鉴点：步骤间参数绑定、实际执行状态和错误消息边界。不必复制其完整双模型解释器；它也不是自动权限编译的完整解法，用户仍需提供和维护安全策略。

## 5. AuthGraph：授权步骤与实际步骤对照

题名意为“对齐来源与授权：大语言模型智能体的双图防御”。重点读3节与附录B：任务与工具目录生成授权图，实际执行形成另一张图，检查工具顺序及参数应该来自哪些步骤。

M3借鉴点：显式表达“搜索→取得对象→读取→修改”，不只保存工具名单。干净规划上下文表示未受外部注入污染，不代表用户意图已被正确编译；不复制其排除场景来提高本项目结果。

## 与本轮实现的关系

本轮独立实现有限任务契约、延迟对象绑定及程序检查，不复制作者代码或实验结果。共同原则是：外部数据可成为任务材料，不能自行生成操作权限；可信对象属性也必须有明确的后端来源，不能由模型或普通字典声明。效果由本轮正常/攻击配对及机制回放检验，不预设优于旧版。
