## 1. 结论先说

现有结果能够支持一篇关于**授权规则、正常任务完成代价和评估口径**的实证论文。它最清楚的发现是：授权规则的具体实现会显著改变正常任务能否完成；只看攻击事件低不低，会漏掉大量执行受阻、失败和未知结果。

当前的主张—原始结果—统计缓存—主表图基本可以追溯，但不能笼统称为“每一条链都完整”。同期校准有2份在线字段投影收据、4份结构化安全收据缺失，四条结局保持未知；本轮也没有读取内部请求日志来独立核验调用前时序。这些事实不能通过补写摘要、填零或重跑成功行消除。

不建议为了让论文显得厚而继续增加大型矩阵。当前最必要的是把样本关系、端点定义、未知处理和论文主线说清楚，然后完成作者确认、真实外部方法审阅与投稿交付准备。若以后要转回“完整防护更有效”的机制论文，才需要新的修复版正式比较。

### 4.1 13/30、11/30是否太少？

这两个数是**同一批30个良性工具任务中成功完成13个、11个**，不是只有13次或11次实验。30个任务分别进入policy/full和两种授权条件，形成配对比较；另一个基准也有30个良性工具任务。反复给这30个任务多跑条件会增加执行条数，却不会自动增加独立样本。

判断“够不够”取决于要证明什么：

| 想回答的问题 | 当前判断 |
|---|---|
| 在这批任务、这个编译器下，自动权限与精确目标是否造成明显完成差异？ | 有支持。2/30对13/30、11/30的配对差区间均排除0，校正后p值也已报告 |
| 能否精确估计总体完成率？ | 精度有限。13/30的Wilson区间为27.38%–60.80%，11/30为21.87%–54.49%，范围较宽 |
| 能否证明full比policy更好？ | 不能由13/30和11/30得到这种结论；需使用任务配对的模块比较，而非只比两个百分数 |
| 能否证明安全提升或普遍有效？ | 当前不足。安全对照事件只有3/30，配对区间跨0，另一个基准无防护本已全零 |

作为直观精度说明，若30个**独立攻击任务**观察到0事件，Wilson 95%上界仍为11.35%；60个为6.02%，100个为3.70%，120个为3.10%。这是统计区间计算，不是新实验、功效分析或“跑够100就一定能发表”的保证。当前490攻击分配重复任务，不能把它们当490独立任务套此界限。

**我的建议：当前30任务可保留为有明显效用差异的配对研究，但别称大规模验证。** 若希望把主要完成率估计做得更稳，下一轮应优先增加真正不同的良性任务和同期活跃攻击对照，而不是重复已成功行。可以先评估每基准60–100个不同任务的可获得性，再按希望排除的差异、配对不一致概率及预设区间宽度做正式样本量设计；本轮不自动启动扩样或API调用。

## 7. 正文怎样改得更直接

按照Nature技能的“主文纪律”，每一部分只承担自己的职责：引言说明问题与比较；方法说明真实设计；结果给出观察和不确定性；讨论解释；局限集中说明边界。

采用既有术语，不为修辞新增同义名词：

| 名词 | 本文固定含义 |
|---|---|
| execution assignment | 一次计划任务—条件执行，不是独立样本 |
| case / underlying task | 案例/底层任务，同一底层任务可有多个攻击实例 |
| auto_compiled | 从可信任务输入自动生成的授权 |
| exact_target_v2 | 给Guard的离线派生精确目标理想对照 |
| unsafe effect | 按基准区分的安全端点：AgentDojo原生评分，M3-v2有执行证据的模拟越权效果 |
| TCR | 良性工具任务完成率，与流程正常结束不同 |
| unknown / failure | 缺结果证据/运行故障；都不等于安全或成功 |

主要修订：

1. RQ1直接比较自动编译授权与修复后精确目标；旧完整参数相等缺陷放实现背景，不暗示有旧匹配器同期cell。
2. 明确120案例严格嵌套180案例、153底层任务及1,396执行的关系，修正原来笼统的“样本重叠”。
3. 删除引言、相关工作和结论反复出现的first/only/SOTA否认，改为直接说明与已有工作的关系。
4. 将低事件、oracle、编译器覆盖、基线适配、缺失、内部归因、历史尾部和泛化范围集中到Discussion的一个Limitations小节；中文同步到“局限性”。
5. 保留效用下降、区间跨零、失败、未知和必要图表定义。这些是结果或方法事实，不因减少防御表达而消失。
6. 图注保留读图所需的样本、区间、未知定义，删除与集中局限重复的泛化清单；当前仓库链接改为Fischl0527/M3_PI_Guard，仍说明私有与归档待完成。
