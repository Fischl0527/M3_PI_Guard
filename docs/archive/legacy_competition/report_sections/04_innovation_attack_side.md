# 4. 攻击侧创新说明

本项目的攻击侧设计从传统“模型回答是否违规”扩展到“智能体工具链行为是否越权”，更贴近 RAG、插件、函数调用和自动化工作流中的实际风险。

## 4.1 从输出安全转向行为安全

传统越狱测试通常观察模型是否生成不当文本。本项目将评测重点放在文件读取、邮件发送、接口调用和代码执行等工具动作上，能够直接衡量提示注入是否导致未授权行为。

## 4.2 多攻击族样本矩阵

样本库同时覆盖：

- 直接越狱与说服性提示
- RAG/文档间接提示注入
- 多语言/T2L 任务切换
- JSON/RPC 结构化字段注入
- 工具输出污染
- 正常样本误报率校准

这种矩阵化设计便于横向比较不同攻击族在 baseline、keyword_only、policy_only 和 full_guard 模式下的表现。

## 4.3 本地授权 mock 靶场

所有危险动作均被约束到本地 sandbox mock 工具。样本使用 canary 假 secret、`.test` 邮箱和 mock API 端点，不访问真实网络，不发送真实邮件，不执行真实恶意代码。

## 4.4 面向检测器的样本标注

样本加入 `risk_tags`、`success_indicators`、`safe_indicators` 和 `expected_detectors` 等字段，使攻击输入可以与行为监督模块的检测原因对齐，便于复核阻断是否准确。

## 4.5 可答辩的代表案例

样本库选择 `RAG-PI-016`、`JSONRPC-001` 和 `MTL-009` 作为演示样本，分别代表不可信文档、结构化数据字段和多语言任务切换三类典型风险。每个案例均配有案例卡，便于说明攻击入口、风险目标、防护原因和安全边界。
